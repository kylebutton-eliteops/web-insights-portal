How to use the Web Insights Portal

Four steps: export logs from ZIA, start the portal, upload, download the CSV. The first run takes about ten minutes to set up; after that it's a couple of minutes per export.

1. Export · 2. Set up · 3. Upload · 4. Read the results · Troubleshooting

1. Export logs from Web Insights

  1. In the ZIA admin console, open Analytics → Web Insights and switch to the Logs view. (Menu names can differ a little in the new Experience Center.)
  2. Pick the time range. Web Insights exports at most 1,000,000 rows, so for a busy tenant use a few hours to a day at a time, or add filters (location, department, policy action).
  3. Add filters if you want: for example Policy Action = Allowed to review what's getting through, or a single location or department.
  4. Open the column picker and make sure these columns are on. The portal skips any that are missing:
    • Required: URL
    • Recommended: Event Time, User, Policy Action, URL Category, URL Super Category, URL Class, Cloud Application, Cloud Application Class, Department, Forwarding Rule, Certificate Chain Validity, ALPN Protocol
    • For "which rule did it hit": any rule-name columns (URL Filtering rule, Cloud App Control rule, SSL Inspection rule). The portal picks up every column with "Rule" in its name and adds it to the output.
  5. Click Export → CSV. Don't open and re-save the file in Excel first; upload it exactly as downloaded.

2. Set up the portal (first time only)

  1. Install Python 3.9 or newer (python3 --version to check).
  2. Open a terminal in the web_insights_portal folder and run:
    • macOS / Linux: ./run.sh
    • Windows (PowerShell): .\run.ps1
    The script creates a private Python environment, installs Flask, pandas and openpyxl, and starts the portal.
  3. Open http://127.0.0.1:5055. The portal only listens on your own computer; nobody else on the network can reach it.
  4. Optional: Zscaler category lookup. To check each host against Zscaler's current categories (not just what was logged), you need a OneAPI client:
    • In ZIA, create a read-only admin role (View Only, URL Categories / URL Filtering view access).
    • In ZIdentity, go to Integration → API Clients → Add, pick Client Secret, and assign the ZIA role.
    • Copy .env.example to .env and fill in ZIA_VANITY_DOMAIN (the part before .zslogin.net in your sign-in address), ZIA_CLIENT_ID and ZIA_CLIENT_SECRET. Or type them into the upload form each time; they aren't saved.

3. Upload and analyze

  1. On the Upload page, choose the CSV you exported.
  2. Tick Also look up current Zscaler categories with OneAPI if you set up credentials. It adds about a minute per 4,500 hosts (Zscaler's API takes 100 hosts a second).
  3. Click Upload and analyze. A 1M-row export takes about a minute without the lookup.
  4. When it finishes, download:
    • Hosts CSV: one row per host, which is usually what you want.
    • All CSVs (.zip): the hosts CSV plus category, SSL, forwarding rule and rule-name summaries.
    • Excel workbook: everything above as tabs. Import it into Google Sheets with File → Import.

The uploaded export is deleted once it's processed (it contains user names). Outputs stay in data/outputs until you delete them, and the Recent runs list clears when you stop the portal.

4. Read the results

Host, Hits, % of hitsThe hostname (URLs de-duplicated by host) and how many log rows it had.

Unique users, Departments, Top departmentsWho depends on the host. Check this before changing policy for it.

URL class, Cloud application, Cloud app classFrom the logs; use them for Cloud App Control planning.
Policy actionWhat happened to the requests (only what you exported; filter on Blocked to see blocks).
Forwarding rule, detailWhich forwarding rule the traffic used, e.g. a Dedicated IP egress rule. "Mixed" means more than one.
Rule-name columnsOnly if the export had them: each rule the host hit, with hit counts.
SSL inspected %, SSL statusWorked out from Certificate Chain Validity: a value means the request was inspected, blank means it wasn't.
SSL bypass reviewExpected: commonly bypassed on purpose (Microsoft 365 / Teams, OS updates, OCSP/CRL, Apple and Google device services, pinned apps). Review: worth checking (financial or health sites, ad-tech, or inspected only some of the time). These labels are pattern-based guesses, not policy.

Troubleshooting

  • "Couldn't find a header row with a URL column": the file isn't a Web Insights CSV, or the URL column was turned off before exporting.
  • Exactly 1,000,000 rows: you hit the export limit. Export shorter time ranges and run each one.
  • "OneAPI sign-in failed (HTTP 401)": check the client ID and secret, and that the vanity domain is only the prefix (e.g. acme, not https://acme.zslogin.net).
  • "Can't reach …zslogin.net": your network or proxy is blocking it. Try off-VPN, or skip the lookup.
  • Lookup errors with HTTP 403: the API client's ZIA role is missing URL lookup access.
  • Port 5055 already in use: start it with PORT=5056 ./run.sh.
  • Upload fails for very large files: the limit is 2 GB. Split the time range.
